# Implementation Plan: 3D Car Parts Selector

**Branch**: `001-car-parts-selector` | **Date**: 2026-11-18 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/001-car-parts-selector/spec.md`

## Summary

This is a single-page, front-end-only inspection demo. The user rotates a stylised 3D car,
taps body panels, glass and wheels (or picks them from a list), and marks each part Pass,
Advisory or Damage with notes. There are five body styles, six camera presets and zone
filters, and the inspection saves automatically on the device.

**Technical approach**:
- Port the inspiration's procedural car generator into a pure, unit-tested TypeScript
  module.
- Render it as one vertex-coloured mesh in React Three Fiber, with parts picked by face
  index.
- Drive the camera with drei `CameraControls`.
- Keep inspection state in a zustand store that saves itself to `localStorage`.
- Build all other UI as plain accessible DOM.
- Lazy-load the 3D scene so the list UI is usable at once and the app still works with no
  WebGL. Details are in [research.md](./research.md).

## Technical Context

**Language/Version**: TypeScript 7.0 (strict), run on Node 22 LTS for tooling

**Primary Dependencies**: Vite 8.3, React 19.3, three 0.187, @react-three/fiber 9.8,
@react-three/drei 10.7 (`CameraControls` only), zustand 5.1
(`persist`), @fontsource-variable/inter

**Storage**: browser `localStorage`, key `car-inspection:v1`, checked against
(removed 2026-11-18: nothing is saved — it's a demo)

**Testing**: Vitest 5 (unit tests plus component tests with @testing-library/react in jsdom),
Playwright 1.65 (end-to-end and smoke tests in Chromium and WebKit against `vite preview`)

**Target Platform**: the latest two versions of Chrome, Edge, Firefox and Safari on desktop
and iOS. WebGL 2 is the baseline, WebGL 1 is accepted, and the list-only fallback works with
no WebGL.

**Project Type**: client-side single-page web app (Vite), with no backend

**Performance Goals**: 60 fps on a laptop with integrated graphics and 30 fps or more on a
mid-range phone. The interactive car appears within 3 s (SC-004). Nothing redraws while
idle.

**Constraints**: entry JavaScript 300 KB gzipped or less, with the 3D chunk lazy-loaded.
Under 10 draw calls per frame. Pixel ratio capped at 2 and lowered adaptively. Works offline
once loaded. No network calls at runtime.

**Scale/Scope**: one screen, five body styles, 24 to 26 parts per style, about 4,000
triangles per car, one inspection at a time, a single user

**Structure Decision**: one Vite app at the repository root, with no backend or packages
folder. `src/vehicles` and `src/state` contain no React and no three.js, so they can be
tested in Node. `src/scene` is the only code that imports three.js and is loaded through
`React.lazy`. `src/ui` is plain React DOM.

## Complexity Tracking

| Deviation | Why it's needed | Why the simpler or required option was rejected |
|-----------|-----------------|-------------------------------------------------|
| Car models are generated by code at runtime, not loaded as compressed glTF/GLB (Principle V) | Every panel, window and wheel must be a separately selectable part, across five body styles. The user chose app-drawn shapes (Clarification Q2), and the inspiration already defines them this way. | glTF would need five licensed models, each split into about 25 named parts. They would be hard to find, and could add up to 25 MB of downloads against a 3 s load target. The generated meshes weigh nothing to download, divide into parts exactly, and can be unit-tested. The parts of Principle V about size and licences are still met, because no assets are downloaded. |

### Update: real models for the SUV and Van

The SUV (BMW X1 STL) and Van ("Van Car 1" OBJ) now load real models, as compressed GLB files
built by `scripts/build-model.mjs`: 476 KB and 67 KB, under Principle V's 5 MB limit. This
brings those two body styles in line with Principle V. The exception above still applies to
Saloon, Hatch and Pickup.

**Saloon and removed styles (later the same day).** The Saloon now uses a Mercedes-Benz W222
GLB (133 KB): wheels come from its named objects and glass from its materials. Hatch and
Pickup are removed, so every body style now uses a real model and Principle V is met for all
three. The drawn shapes remain only as a fallback if a model fails to load.

**Still open: the source and licence of all three models.** Principle V requires them to be
recorded, so they are marked TODO in `public/LICENSES.md`.

- **Splitting into parts.** `src/vehicles/modelSegmentation.ts` assigns each triangle to a part
  from its position and facing, using landmarks measured on each model. For the van it also
  uses the OBJ groups (wheels, front doors) and materials (glass). On the low-poly van, long
  edges are subdivided first so part boundaries follow the measured lines.
- **New dependencies.**
  - `three-mesh-bvh`: fast picking on the 150k–178k triangle meshes.
  - `suspend-react`: already used by React Three Fiber, now declared directly.
  - `@gltf-transform/*` and `meshoptimizer`: development only, for the conversion script.
